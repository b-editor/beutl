# 空プロジェクトの作成・開く・閉じる処理の性能改善

2026-09-16。空の新規プロジェクトでも遅いという報告を受け、Git管理あり・なしの作成、初期化、終了、再オープンを調査した。

## 原因と修正

### macOSのパス確認が無関係なフォルダー内容に比例する

`FilePathComparison`は、既存の各パス要素の正しい表記を得るため、親フォルダーを全件列挙して辞書を作成していた。空プロジェクトでもこの確認は多数行われ、Git用の一時ファイルやプロジェクトの祖先フォルダーが大きいと、作業量・割り当て量が増える。

実際の通常の一時フォルダーで、空プロジェクトの作成と単独のパス比較が数分間進まない状態を再現した。ネイティブスタックは`SystemNative_ReadDir` → `readdir` → `__getdirentries64`で待機しており、開かれていたディレクトリはユーザーの一時フォルダーだった。この測定は中断し、比較用の計測は専用の一時フォルダーでも実施した。

macOSでは`getattrlist(ATTR_CMN_NAME, FSOPT_NOFOLLOW)`から対象エントリーの名前を直接取得するようにした。シンボリックリンクは従来の要素単位の処理で解決し、リンク後の`..`の意味を維持する。`opendir`で親の読み取り権限も確認し、列挙不可の祖先に対する厳格な問い合わせの拒否を保つ。未対応ファイルシステム、失敗、不正な属性バッファは既存の列挙方式へ戻す。WindowsとLinuxは従来の方式を使用する。

macOS SDKの`sys/attr.h`と`getattrlist(2)`でABIを確認した。返却長、相対オフセット、終端、UTF-8、パス区切り、ドット要素を検査し、不正な結果は使わない。

参照: [Appleのgetattrlist仕様](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/getattrlist.2.html)。

### Git/LFSの検出を繰り返していた

プロジェクト切り替えでは一時的なバックエンドも作られる。一つのバックエンド内で検出結果を保持していても、共有する`GitInstallationLocator`は毎回GitとGit LFSを起動していた。空プロジェクトをGit管理あり・なしで作成・開閉する再現では、バージョン確認がそれぞれ14回発生した。

成功した検出結果をLocator内で5秒間再利用する。実行ファイル設定、PATH/PATHEXT、ProgramFiles、DEVELOPER_DIR/TOOLCHAINS、作業ディレクトリが変われば再検出する。Git未検出、古すぎるGit、タイムアウトした検出は保持しない。呼び出し元のキャンセルも引き続き優先する。 同じ条件の検出が進行中なら、そのGit/LFSプローブを共有する。各呼び出し元は自分の待機だけをキャンセルし、待機者がいなくなった時点でプローブをキャンセルする。設定の異なる検出は独立して進め、破棄した検出の遅延結果で新しい検出やキャッシュを置き換えない。

### システムGitの起動用ラッパーを毎回経由していた

macOSの自動検出で`/usr/bin/git`が選ばれた場合、開発ツールの存在確認後に`xcrun --find git`で現在の実体を取得する。以後のコマンドは、その実体を直接起動する。ユーザーが明示した実行ファイルはそのまま使用し、解決失敗時は元の起動方法に戻す。

この環境では、ラッパーと実体で`--exec-path`が一致することを確認した。7回の単独起動の中央値は約25msと11msだった。開発ツールが未インストールの場合は解決を行わず、従来どおりシステムGitのインストール誘導を避ける。

## 検証・計測の扱い

- パス比較50回、隣接ファイル5,000件の再現: 約1,194ms / 143.4MiB割り当て → 約25ms / 0.6MiB。ネイティブ経路の親フォルダー列挙は0回。
- Git trace2による同じ操作列: Git/LFSのバージョン確認が各14回 → 各5回、記録されたGitプロセス起動が174回 → 129回。Git LFS内部のGit起動も含む。
- 通常の一時フォルダーを使う空プロジェクトの作成・再オープン・終了も、修正後はGit管理あり・なし双方で完了した。
- 作成・開閉のHeadless UIテスト40件が通過。保存失敗時の終了中止、未保存内容の終了時スナップショット、保存せず閉じる動作も含む。最終の単独計測2件も通過した。
- パスの同一性、Unicode、ハードリンク、シンボリックリンクと`..`、列挙不可の祖先、壊れたネイティブバッファ、検出結果の有効期間・設定変更・キャンセルを検証するテストを追加した。
- 最終の関連単体テストは189件中187件通過、環境依存2件スキップ。一括実行はマシン高負荷時に終了処理の既存5秒制限で2件タイムアウトしたため中断した。この2件は絞り込んだ再実行では両方通過した。再実行では、自動検出が選ぶものと同じXcode内のGitを一時的にPATHの先頭へ配置した。全ソリューションのテスト完了は主張しない。

空プロジェクト・Git管理ありの参考値（作成にはGit初期化を含む）:

| 操作 | 変更前 | 最終の単独計測 |
| --- | ---: | ---: |
| 作成＋Git初期化 | 6.09秒 | 3.66秒 |
| 開く | 1.75秒 | 0.87秒 |
| 再オープン後に閉じる | 3.41秒 | 1.47秒 |

実行中にマシンの負荷が大きく変動した（8コア環境でロードアベレージが30を超えた時点もある）。作成・開閉全体の時間には初回初期化や他プロセスの負荷も入るため、上記を実プロジェクト全体の時間短縮率として扱わない。主な回帰条件は、列挙しないこと、重複した検出を省くこと、および既存の保存・復旧動作を維持することである。
