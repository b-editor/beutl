# `beutl/analytics-features.v1.json` Contract

The manifest is optional static package content. It is packed by `Beutl.Extensibility.Sdk` from the project property `BeutlAnalyticsFeaturesManifest`, defaulting to `beutl.analytics.json` when that file exists.

`types` is an array of `{ "assembly": "…", "type": "…" }` objects. Validation limits are 64 KiB, **1 through 128 features**, 8 types per feature, `kind` matching `[a-z][a-z0-9-]{0,31}`, `key` matching `[a-z][a-z0-9-]{0,63}`, assembly/type values of 1 through 256 characters with no relative names, and no duplicate kind/key or assembly/type assignment. Unknown fields reject the whole manifest. The canonical Marketplace package ID is lowercase, at most 100 characters, and matches `[a-z0-9](?:[a-z0-9.-]{0,98}[a-z0-9])?`. Before any declared extension assembly is loaded, the client rehashes the persisted `.nupkg`, matches that SHA-256 to approved release metadata, reloads the approved manifest from both the archive and installed directory, compares the extracted DLL bytes with the archive entries, and loads only the immutable verified archive bytes. The client accepts at most 64 MiB of persisted artifact bytes and 64 MiB of captured managed assembly bytes; larger payloads remain generic. Packages containing in-package `runtimes/**/native/**` assets remain generic because an OS native loader cannot consume the managed immutable-byte snapshot. An exact-attribution package is loaded from the snapshot, so `Assembly.Location` is intentionally empty and is not a package-root API; a package that needs legacy path discovery must omit the manifest and remain generic. Exact IDs use `extension/<canonical-marketplace-package-id>/<kind>/<key>`; any unavailable or mismatching evidence yields generic attribution.
