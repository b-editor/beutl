### New Rules

Rule ID | Category | Severity | Notes
--------|----------|----------|-------
BESG001 | Beutl.Engine.SourceGenerators | Warning | EngineObjectResourceGenerator
BESG002 | Beutl.Engine.SourceGenerators | Warning | FallbackTypeGenerator
BESG003 | Beutl.Engine.SourceGenerators | Warning | MetadataCallbackPurityAnalyzer, covering the render metadata contracts, the shader binding builders, and the execution callback of a definition builder (OpaqueRenderDefinition, TargetScopeDefinition, TargetCommandDefinition, RawTargetScopeDefinition, RawTargetCommandDefinition, GeometryDefinition); a callback named through a readonly field or a get-only property is judged by the delegate that field was initialised with or that getter returns, because such a member fixes only the reference and not what the delegate carries; a property with a setter is reported outright, and so is a member whose source is not in the compilation - one from a referenced assembly, a readonly field assigned in a constructor, or a getter that is not a single returned expression
BESG004 | Beutl.Engine.SourceGenerators | Warning | MetadataCallbackPurityAnalyzer, over the same calls BESG003 covers, best-effort: it sees only the static fields and properties named directly by the callback body - the lambda written at the call, or the lambda reached through a readonly field or a get-only property; a static field passes when it is const, or readonly and of a type whose instances carry no writable state - an enum, a primitive, string, decimal, DateTime, a RenderResourceSlot<T>, or a readonly struct or sealed class whose every instance field, inherited ones included, is itself readonly and of such a type, walked to a bounded depth - so a static readonly field of a type carrying a writable field, of an unsealed class, or of a delegate is reported; that walk is only run where the field list is the whole type, meaning a type declared in the compilation or a struct, because a class from another assembly is imported down to its public and protected members and its field list is then a floor and not the type, so a static readonly field of one is reported however immutable the visible members look; a static property passes only when its getter - expression-bodied, a single return, or the initialiser of a get-only auto-property - yields a compile-time constant, an enum member, default, or a static readonly field that same test accepts, so every other getter is reported, including one whose source is not in the compilation; all of that is read out of the callback's own body, and a method group is read the same way a lambda is - the method it names is followed to its declaration and walked - so a method group whose body has no source in this compilation is reported, the body being the whole of the callback; from inside a body the walk follows the static methods that body names, and the methods those name, to a bounded depth, reporting a chain longer than the bound rather than accepting it, while a callee whose body has no source here is where the walk stops without reporting; the same walk and the same bound enter what a body runs without naming - a constructor, meaning its own body, the constructor it chains to, the base constructor it runs without saying so, and the instance field and property initialisers that run with it, and a user-defined operator or conversion, an implicit conversion included; what a callee with no source here reads and whatever an instance member computes - an indexer, a property getter, a method called on a value - both stay invisible
BESG005 | Beutl.Engine.SourceGenerators | Warning | RenderNodeChangeMarkingAnalyzer, best-effort: it reports only a direct assignment, written inside the node's own type, to an instance field, an auto-property, or the backing store a property names with the field keyword, that the node's Process reads - Process meaning the override filling the RenderNode slot, inherited or not, and not a same-named overload declared beside it - with no MarkChanged() call on that node reachable from the assigning member; an assignment made through another type, through a virtual call, by mutating a collection in place, on a branch that skips a MarkChanged() call written elsewhere in the same member, or inside Process itself (where memoization is legitimate) all stay invisible, and a MarkChanged() call on some other node does not excuse it however it is spelled - qualified, conditional as other?.MarkChanged(), or reached through a helper invoked on that other node - so the runtime cross-check in Beutl.Engine - not this rule - is what covers them
