BESG003 | Beutl.Engine.SourceGenerators | Warning | MetadataCallbackPurityAnalyzer, covering the render metadata contracts, the shader binding builders, and the execution callback of a definition builder (OpaqueRenderDefinition, TargetScopeDefinition, TargetCommandDefinition, RawTargetScopeDefinition, RawTargetCommandDefinition, GeometryDefinition); a non-static lambda is judged by what it closes over - one that reads nothing, or nothing but the RenderNode it is written inside, is accepted, because that node arrives as the delegate's own target, marking it changed re-records it, and an answer of its that moves is caught by the recorded-answer cross-check, while one closing over a local, over a parameter, or over an enclosing instance that is not a RenderNode is reported, and so is one whose closure this rule could not read; a method group takes that same exemption, because the exemption is about which instance the callback reads and not about how it was written - one naming a method of the RenderNode it is written inside is accepted, while one bound to any other instance is reported, whether that receiver is an object the author holds elsewhere, a value type the conversion boxes, or an enclosing instance that is not a RenderNode, and a local function that is not declared static is reported because this rule does not read what it closed over; a callback named through a readonly field or a get-only property is judged by the delegate that field was initialised with or that getter returns, because such a member fixes only the reference and not what the delegate carries; a property with a setter is reported outright, and so is a member whose source is not in the compilation - one from a referenced assembly, a readonly field assigned in a constructor, or a getter that is not a single returned expression
BESG004 | Beutl.Engine.SourceGenerators | Warning | MetadataCallbackPurityAnalyzer, over the same calls BESG003 covers, best-effort: it sees only the static fields and properties named directly by the callback body - the lambda written at the call, or the lambda reached through a readonly field or a get-only property; a static field passes when it is const, or readonly and of a type whose instances carry no writable state - an enum, a primitive, string, decimal, DateTime, a RenderResourceSlot<T>, or a readonly struct or sealed class whose every instance field, inherited ones included, is itself readonly and of such a type, walked to a bounded depth - so a static readonly field of a type carrying a writable field, of an unsealed class, or of a delegate is reported; that walk is only run where the field list is the whole type, meaning a type declared in the compilation or a struct, because a class from another assembly is imported down to its public and protected members and its field list is then a floor and not the type, so a static readonly field of one is reported however immutable the visible members look; a static property passes only when its getter - expression-bodied, a single return, or the initialiser of a get-only auto-property - yields a compile-time constant, an enum member, default, or a static readonly field that same test accepts, so every other getter is reported, including one whose source is not in the compilation; all of that is read out of the callback's own body, and a method group is read the same way a lambda is - the method it names is followed to its declaration and walked - so a method group whose body has no source in this compilation is reported, the body being the whole of the callback; from inside a body the walk follows the static methods that body names, and the methods those name, to a bounded depth, reporting a chain longer than the bound rather than accepting it, while a callee whose body has no source here is where the walk stops without reporting; the same walk and the same bound enter what a body runs without naming - a constructor, meaning its own body, the constructor it chains to, the base constructor it runs without saying so, and the instance field and property initialisers that run with it, and a user-defined operator or conversion, an implicit conversion included; an instance member is walked on those same terms when the expression makes the instance it runs on, because an object creation names the exact type it makes - so the member the call binds to is the member that runs - and what that instance carries came from the constructor and initialisers the walk already reads, while a property or indexer contributes the accessor the reference actually runs, the getter for a read and the setter for an assignment, an auto-property's bodiless accessor being the no-source case; what a callee with no source here reads, and what an instance member computes on a receiver the call did not make, both stay invisible - the second deliberately, because these callbacks are handed the objects they work through, so following a member called on one of those walks the render backend behind it
BESG005 | Beutl.Engine.SourceGenerators | Warning | RenderNodeChangeMarkingAnalyzer, best-effort: it reports two shapes, both about state the node's Process reads - Process meaning the override filling the RenderNode slot, inherited or not, and not a same-named overload declared beside it. The first is a direct assignment, written inside the node's own type, to an instance field, an auto-property, the backing store a property names with the field keyword, or an element of one of those - _points[0] = value - with no MarkChanged() call on that node reachable from the assigning member. The second is a declaration: an auto-property the node's own type declares whose setter is neither private nor init-only, because such a setter is synthesized and is assigned by whoever holds the node, so there is no body for the first shape to read and no assignment inside the type for it to find - the fix being to give the setter a body that marks, or to narrow it to private or init so that only the node's own code can assign it. An assignment made through another type, through a virtual call, by a method that mutates a collection in place such as list.Add(x), past the name to a member of whatever the state holds such as _child.Bounds = value, on a branch that skips a MarkChanged() call written elsewhere in the same member, to state a base type declares (reported where that type is analyzed), or inside Process itself (where memoization is legitimate) all stay invisible, and a MarkChanged() call on some other node does not excuse it however it is spelled - qualified, conditional as other?.MarkChanged(), or reached through a helper invoked on that other node - so the runtime cross-check in Beutl.Engine - not this rule - is what covers them
